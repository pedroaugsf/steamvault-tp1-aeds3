Anatomia

Como um jogo vira bytes

O arquivo abre com um inteiro guardando o último id usado. Depois vêm os registros, um atrás do outro: lápide, tamanho, dados. Clique numa faixa para ver o campo destacado no dump — ou em “ver os bytes” em qualquer card do explorador.

CREATE

Sempre no fim

Lê o último id do cabeçalho, incrementa, regrava os 4 bytes iniciais e escreve o registro no fim do arquivo.

UPDATE

Dois caminhos

Mesmo tamanho, regrava no lugar. Tamanho diferente, o antigo recebe lápide e a nova versão vai para o fim, com o id preservado.

DELETE

Só um byte muda

Exclusão lógica: a lápide vira '*'. O espaço continua ocupado até a ordenação externa passar.

Ordenação externa

Ordenar o que não cabe na memória

O arquivo é quebrado em blocos ordenados, distribuídos entre N arquivos temporários, e intercalado até sobrar um bloco só. Mexa em N e em M e veja as passadas encolherem — a simulação roda o mesmo algoritmo do sistema.

Testes e medições

40 verificações, sem interação

A bateria confere a carga, os dois cenários de update, a exclusão lógica, a inclusão e a ordenação externa em todas as chaves nos dois modos — lendo o arquivo de volta e comparando par a par se ficou ordenado, se as lápides sumiram e se nenhum registro se perdeu.

Como rodar

Um JDK e nada mais

Requisito único: JDK 17 ou superior. Nenhuma biblioteca externa, nenhum gerenciador de dependências, nenhum banco a instalar.

:: Windows
compilar.bat     :: compila src\ para bin\
executar.bat     :: abre o menu principal
testar.bat       :: roda as 40 verificações
# Linux, macOS, Git Bash
./executar.sh            # menu principal
./executar.sh testes     # bateria de testes
:: recoletar a base do zero, direto das APIs públicas
java -cp bin tp1.coleta.ColetorSteam dados/steam.csv
src/tp1/
├── app/        Main (menu)  ·  Testes (bateria automatizada)
├── modelo/     Registro (contrato)  ·  Jogo (entidade e serialização)
├── arquivo/    ArquivoSequencial<T> (CRUD)  ·  CargaCSV (parser próprio)

├── coleta/     ColetorSteam · Json · PrepararSite   (ferramentas)
└── util/       Terminal (entrada e saída robustas)

De onde vêm os dados. A base é montada por um coletor próprio que cruza três fontes públicas pelo appid: o SteamSpy traz desenvolvedora, preço e avaliações; uma chamada por gênero monta a lista de gêneros; e a busca da loja Steam fornece a data de lançamento, que nenhuma das outras entrega em massa. Sobram no CSV apenas os jogos presentes nas três — registros completos. Jogos ainda não lançados são descartados.
